## 1.  현재 상황

1.  기획

	- 실험과 개발이 동시에 이루어져 기획 변경이 동반되는 구조
	
2. Git 브랜치

	- 단일 브랜치로 개발/QA/시연 진행 중

3. 프론트엔드 개발 환경

	- 기획 변경 후 빠른 피드백을 위한 push가 필요하다고 생각
	- 사용자 경험을 위해 push 후 QA에 도움 요청이 필요한 상황

---
## 2. 이슈 사항

1. 기획 변경으로 화면 UI가 변경 된다면, 그 변경된 UI/UX 내용을 명확하게 프론트 에서 이해가 필요.

	- 기능이 어떻게 진행되어야 하는지 알기가 어려워 push 후 QA까지 요청이 가야하는 상황
	
2. 개발 중인 프로덕트가 고객 시연에 사용되는 것에 대한 개인 의견

	- 프론트엔드 개발을 진행하고 있는 저로서는  미완성된 화면을 팀원이 고객 앞에 보여주는 것이 좀 부담되옵니다... 프라이드가 있지.. ㅠ
   
3. 긴급 수정 시 배포 리스크 증가

---

## 3. 고려 사항

### 1. Git 브랜치 전략 개선

```
main (시연용) ← develop (개발 및 QA)
```

- **develop**: 일상 개발 작업
- **main**: 시연/데모용 (QA 통과 후에만 머지)


### 3. 프론트엔드 기획 관리

- 기획 확정 후 개발 시작 
- 주요 변경 사항은 다음 스프린트로 이관
- 필요 시 주간 기획 리뷰 미팅
- 변경 우선순위 협의 프로세스
