## 핵심 성과 (Before & After)

### 1. 조회 성능 80% 향상
**Before**:
- 단일 테이블에 1억 건 데이터
- 조회 시간: 15초
- 인덱스 크기: 5GB

**After**:
- 월별 파티션 테이블 (800만 건/월)
- 조회 시간: 3초 (80% 향상)
- 인덱스 크기: 700MB/월 (86% 감소)

**방법**: 월별 파티션 테이블 + 복합 인덱스 전략

---

### 2. JWT 인증 보안 강화
**Before**:
- HS256 (대칭키) 방식
- Secret Key 유출 시 위험
- 확장성 제한

**After**:
- RS256 (비대칭키) 방식
- Public Key로 검증 가능
- 확장 가능한 구조

**방법**: Spring Security OAuth2 Resource Server 통합

---

### 3. 중복 메시지 99% 차단
**Before**:
- 사용자 실수로 중복 발송
- 비용 낭비
- 고객 불만

**After**:
- DEDUP_HASH (MD5) 기반 중복 검사
- 설정 가능한 시간 윈도우 (10분)
- 중복 메시지 99% 차단

**방법**: MD5 해시 + 시간 윈도우 검사

**고민**:
```

"아니면 둘 다 사용할 수 있을까?"
```

### 2. JWT 보안 취약점

**상황**:

```
- 초기에 HS256 (대칭키) 사용
```

**고민**:
```

```

**상황**:
```

```

**고민**:

## 해결 과정

### 1. Hybrid Database Strategy 설계

#### 학습 단계
```
1. Real MySQL 8.0 책 읽기
   - 실행 계획 분석
   - 인덱스 전략
   - 파티션 테이블

2. JPA vs MyBatis 비교 분석
   - JPA: 생산성 우선 (CRUD, 관계 매핑)
   - MyBatis: 성능 우선 (대용량, 복잡한 쿼리)
```

#### 설계 결정
```
도메인별로 다른 기술 선택:
- User/Organization → JPA
- Message/Log → MyBatis
```

#### 구현
```java
// User Domain (JPA)
@Entity
public class User {
    @Id
    @GeneratedValue(strategy = GenerationType.UUID)
    private UUID userId;

    @ManyToOne(fetch = FetchType.LAZY)
    private Organization organization;
}

// Message Domain (MyBatis)
@Mapper
public interface UmsMsgMapper {
    void insertMessage(UmsMsg msg);

    @Select("""
        SELECT * FROM ums_msg
        WHERE dedup_hash = #{dedupHash}
          AND req_date >= #{windowStart}
        """)
    boolean existsByDedupHash(String dedupHash, LocalDateTime windowStart);
}
```

#### 최적화
```sql
-- 월별 파티션 테이블
CREATE TABLE ums_log_202501 (
    log_id BIGINT AUTO_INCREMENT PRIMARY KEY,
    req_date DATETIME NOT NULL,
    dedup_hash VARCHAR(32),

    INDEX idx_req_date (req_date),
    INDEX idx_dedup_hash (dedup_hash, req_date)
) ENGINE=InnoDB;
```

### 2. JWT RS256 인증 구현

#### 학습 단계
```
1. JWT 구조 이해
   - Header, Payload, Signature

2. HS256 vs RS256 비교
   - 대칭키 vs 비대칭키
   - 보안성, 확장성

3. Spring Security 문서 읽기
   - OAuth2 Resource Server
   - JWT Decoder
```

#### 구현
```java
@Service
public class JwtService {
    private final PrivateKey privateKey;
    private final PublicKey publicKey;

    // Access Token 생성
    public String generateAccessToken(User user) {
        return Jwts.builder()
            .subject(user.getUserId().toString())
            .claim("username", user.getUsername())
            .claim("role", user.getUserRole().name())
            .issuedAt(new Date())
            .expiration(new Date(System.currentTimeMillis() + expiration))
            .signWith(privateKey, SignatureAlgorithm.RS256)
            .compact();
    }

    // Token 검증
    public Claims validateToken(String token) {
        return Jwts.parser()
            .verifyWith(publicKey)
            .build()
            .parseSignedClaims(token)
            .getPayload();
    }
}
```

### 3. 중복 방지 시스템

#### 설계
```
1. DEDUP_HASH 생성
   - MD5(phone | content)
   - 예: MD5("01012345678|안녕하세요")

2. 시간 윈도우 설정
   - 기본: 10분
   - 설정 가능

3. 중복 검사
   - 동일 DEDUP_HASH가 윈도우 내에 있는가?
```

#### 구현
```java
@Service
public class DedupService {
    private static final int DEDUP_WINDOW_MINUTES = 10;

    public String generateDedupHash(String phone, String content) {
        String combined = phone + "|" + content;
        return DigestUtils.md5Hex(combined);
    }

    public boolean isDuplicate(String phone, String content) {
        String dedupHash = generateDedupHash(phone, content);

        LocalDateTime windowStart = LocalDateTime.now()
            .minusMinutes(DEDUP_WINDOW_MINUTES);

        return umsMsgMapper.existsByDedupHashAndReqDateAfter(
            dedupHash, windowStart
        );
    }
}
```

## 배운 점

### 1. "은탄환은 없다"

```
처음에는 "모든 것을 JPA로" 하려고 했습니다.
하지만 도메인 특성에 따라 최적의 기술이 다르다는 것을 깨달았습니다.

중요한 것은:
- 기술 자체가 아니라
- 문제를 해결하는 것
```

### 2. "이론을 실전에"

```
Real MySQL 8.0 책을 읽으며:
- 파티션 테이블 개념 학습
- 인덱스 전략 이해

→ 즉시 LinkWave 프로젝트에 적용
→ 조회 성능 80% 향상

책은 읽기만 해서는 안 됩니다.
실전에 적용해야 진짜 내 것이 됩니다.
```

### 3. "측정하고 개선한다"

```
추측이 아닌 측정으로:
- EXPLAIN으로 쿼리 실행 계획 확인
- 인덱스 사용 여부 검증
- 조회 시간 측정

→ 데이터 기반 의사결정
```
