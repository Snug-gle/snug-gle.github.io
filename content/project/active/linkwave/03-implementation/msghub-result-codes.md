# LG U+ MessageHub 결과 코드 레퍼런스

## 개요

**LG U+ MessageHub**는 SNAP 에이전트를 통해 SMS, LMS, MMS, KKO, RCS, RBC 등을 발송하는 플랫폼입니다. 발송 후 결과는 결과 코드(result code)로 반환됩니다.

**핵심: 유일한 성공 코드는 `10000`입니다.**

| 코드 | 의미 | 재시도 | 비고 |
| :--- | :--- | :---: | :--- |
| **10000** | **성공** | ✗ | 유일한 성공 코드 |

나머지 모든 코드는 **실패**입니다.

---

## 결과 코드 체계

### 카테고리 분류

```
1xxxx  ← 성공 (10000만 정의)
2xxxx  ← 공통 오류 (필수 파라미터 등)
3xxxx  ← 발송 오류 (단말 거부, 스팸 등)
5xxxx  ← RCS 오류
6xxxx  ← RBC 오류
```

| 코드 | 설명 | 상태 | 재시도 | 비고 |
| :--- | :--- | :---: | :---: | :--- |
| 32114 | KKO 성공 불확실 | ? UNCERTAIN | ✗ | SNAP이 최종 판정 후 기록 |

**특수성:**
- 실시간이 아니라 최종적으로 SNAP이 성공 또는 실패로 판정
- 32114는 **임시 상태가 아니라 최종 기록**
- 재시도하면 안 됨

## 코드별 대응 방안

### 클라이언트 관점

**사용자가 할 수 있는 재시도:**
- 30120, 30122 (단말기 거부): 나중에 다시 보내기
- 20005 (Rate limit): 잠시 기다렸다가 재시도

**클라이언트가 할 수 없는 실패:**
- 20001, 20002 (파라미터 오류): 메시지 내용 확인 필요
- 30131 (메시지 길이 초과): 내용 축약
- 30130 (스팸 판정): 콘텐츠 검토

### 백엔드 관점 (LinkWave)

**SNAP 시뮬레이터에서:**
```java
// 성공 (매우 높은 확률)
String successCode = "10000";

// 실패 (낮은 확률)
String failCode = "30122"; // 단말기 착신거부 (가장 흔함)
// 또는: "30110" (번호 오류), "30131" (길이 초과)
```

**실제 운영에서:**
- 모든 비-10000 코드 → FAILED 처리
- 실패 이유를 `result_code` 필드에 기록
- 대시보드에서 "top 10 failure codes" 모니터링

## 설계 결정: SUCCESS / FAILED 2가지 분류

### 초안: 4가지 상태

```
SUCCESS    (10000)
FAILED     (모든 3xxxx, 5xxxx, 6xxxx)
RETRYABLE  (30120, 30122, 20005 - 재시도 가능)
UNCERTAIN  (32114 - 최종 결정 대기)
```

### 논의 결과: 2가지로 단순화

#### 1. RETRYABLE 제거 이유

**가정**: ums_log에 기록된 시점 = SMSC/SNAP이 **이미 최종 처리 완료**

```
SNAP의 역할:
1. ums_msg 읽음
2. 통신사 전송
3. 결과 수신 → ums_log 기록

→ ums_log에 30122가 기록됐다면,
  이미 SNAP이 최종 처리를 마침
  (재시도할 권리가 없음)
```

따라서 30122는 RETRYABLE이 아니라 FAILED이다.

#### 2. UNCERTAIN 제거 이유

**SMS/MMS 흐름:**
```
SNAP → SMSC → (대기/재시도) → 최종 결정 → 콜백
               ↑ SMSC 내부 처리 (LinkWave가 개입 불가)
```

**KKO (32114) 흐름:**
```
SNAP → 카카오 → (분석 중) → SNAP이 최종 결정 → ums_log INSERT
                              (성공 또는 실패로)
```

→ ums_log에 32114가 기록됐다면, 그것이 SNAP의 **최종 판정**이다.
→ "불확실" 상태는 없다. SUCCESS 또는 FAILED로만 존재한다.

### 최종 상태 모델

```
ums_msg INSERT
    ↓
SNAP 처리 (1~2초)
    ↓
ums_log INSERT (최종 상태)
    - 10000 → SUCCESS
    - 그 외 → FAILED (재시도 불가)
    ↓
MessageHistory UPDATE
    - status = SUCCESS or FAILED
    - result_code = 실제 코드 저장
```

## 모니터링 및 알림

### 주의해야 할 패턴

**Spike in 30122:**
```
# SELECT COUNT(*) FROM ums_log_202603 WHERE result_code = '30122'
# 일반: 1~5% | 문제: 10% 이상
→ 수신자 네트워크 문제 또는 스팸 판정 위험
→ 발송 시간대 또는 메시지 내용 검토 필요
```

**30131 (길이 초과):**
```
# 이 코드가 나온다는 것 = API 클라이언트 버그
→ 백엔드에서 사전 검증 강화 필요
```

**20005 (Rate limit):**
```
# TPS 초과 → 큐 시스템 적용 또는 대역폭 증설 필요
```
