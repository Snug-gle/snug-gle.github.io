## 1. 프로젝트 개요

### 1.1 프로젝트 배경

현재 문자 발송 시스템의 문제점:
- ❌ 레거시 시스템의 유지보수 어려움
- ❌ 모놀리식 구조로 인한 확장성 제한
- ❌ 최신 기술 스택 미적용
- ❌ 사용자 경험 개선 필요

### 1.2 프로젝트 목표

**LinkWave**는 다음을 목표로 합니다:

```
┌─────────────────────────────────────────────────────────┐
│  🎯 목표 1: 현대적인 기술 스택으로 프로토타입 개발     │
│  🎯 목표 2: 사용자 친화적인 웹 인터페이스 제공         │
│  🎯 목표 3: 확장 가능한 아키텍처 설계                  │
│  🎯 목표 4: CI/CD 파이프라인 구축                      │
└─────────────────────────────────────────────────────────┘
```

### 1.3 프로젝트 범위

**Phase 1 - 프로토타입 (현재)**
- ✅ SMS, LMS, MMS 발송 기능
- ✅ 웹 기반 사용자 인터페이스
- ✅ 발송 이력 조회
- ✅ 주소록 관리
- ✅ 예약 발송

**Phase 2 - 확장 (향후)**
- 📅 카카오톡 알림톡/친구톡
- 📅 RCS 메시지
- 📅 통계 대시보드 고도화

## 2. 시스템 아키텍처

### 2.1 전체 구성도

```
┌──────────────────────────────────────────────────────────────┐
│                        사용자 (고객사)                        │
└──────────────────────────────────────────────────────────────┘
                            ↓ HTTPS
┌──────────────────────────────────────────────────────────────┐
│                      Nginx (Port 80/443)                      │
│  • SPA 라우팅 (React Router)                                 │
│  • API 프록시 (→ Backend)                                    │
│  • 정적 파일 서빙                                            │
│  • Gzip 압축, 캐싱                                           │
└──────────────────────────────────────────────────────────────┘
        ↓ 정적파일                          ↓ API 프록시
┌────────────────────┐            ┌──────────────────────┐
│   Frontend         │            │   Backend            │
│   (React 18)       │            │   (Spring Boot 4.0)  │
│                    │            │                      │
│  • Zustand         │            │  • REST API          │
│  • TanStack Query  │            │  • JWT 인증          │
│  • TypeScript      │            │  • JPA/Hibernate     │
└────────────────────┘            └──────────────────────┘
                                            ↓
                    ┌───────────────────────────────────┐
                    │    데이터베이스 (MySQL 8.0)       │
                    ├───────────────────────────────────┤
                    │  Web DB          Message DB       │
                    │  • 사용자        • 발송 요청      │
                    │  • 주소록        • 발송 이력      │
                    │  • 보관함        (ums_msg)        │
                    └───────────────────────────────────┘
```

### 2.2 데이터베이스 분리 전략

**왜 DB를 분리하는가?**

```
┌─────────────────────────────────────────────────────────┐
│                    Web DB (웹 서비스용)                 │
│  • 목적: 사용자 인터페이스 및 부가 기능                │
│  • 특징: 빈번한 읽기/쓰기, 사용자 경험 최적화           │
│  • 테이블: 회사, 사용자, 주소록, 보관함                │
└─────────────────────────────────────────────────────────┘
                        ↓ 동기화 모듈
┌─────────────────────────────────────────────────────────┐
│                  Message DB (발송용)                    │
│  • 목적: 메시지 발송 처리 및 이력 관리                 │
│  • 특징: 대용량 처리, 발송 성능 최적화                  │
│  • 테이블: ums_msg (발송 요청), ums_log (이력)         │
└─────────────────────────────────────────────────────────┘
```

**장점:**
- 🚀 **성능 최적화**: 각 DB를 용도에 맞게 튜닝
- 📊 **부하 분산**: 사용자 트래픽과 발송 부하 분리
- 🔧 **확장성**: 독립적으로 스케일 업/아웃
- 🛡️ **장애 격리**: Web DB 장애 시에도 발송 시스템 정상 동작

### 2.3 메시지 발송 플로우

```
1️⃣  사용자가 웹에서 메시지 작성 및 발송 요청
         ↓
2️⃣  React 앱 → Spring Boot API 호출
         ↓
3️⃣  백엔드 검증 (발신번호, 내용, 중복 여부)
         ↓
4️⃣  Web DB에 주소록/보관함 저장 (필요시)
         ↓
5️⃣  Message DB (ums_msg)에 발송 요청 저장
         ↓
     TRAFFIC_TYPE 결정
     • real: 실시간/중요 (즉시)
     • normal: 일반 (준실시간)
     • batch: 대량/예약 (배치)
         ↓
6️⃣  사용자에게 응답 반환
     {
       "clientKey": "20251203143000_CompanyA_A3F8D2",
       "status": "ACCEPTED",
       "recipientCount": 100
     }
         ↓
7️⃣  [발송 에이전트] Message DB 폴링 및 발송
     (웹페이지는 여기까지만 담당)
```

## 5. 인프라 구성

### 5.1 서버 디렉토리 구조

```
/opt/linkwave/
├── backend/                        # 백엔드 애플리케이션
│   ├── current/                   # 현재 버전 (심볼릭 링크)
│   │   └── linkwave-backend.jar
│   ├── releases/                  # 릴리스 히스토리
│   │   ├── 20250103-120000/      # 이전 버전
│   │   ├── 20250103-130000/      # 이전 버전
│   │   └── 20250103-140000/      # 최신 버전 ← current가 가리킴
│   ├── shared/                    # 공유 설정
│   │   ├── application-prod.yml
│   │   └── .env (DB 비밀번호 등)
│   └── logs/                      # 애플리케이션 로그
│
├── frontend/                       # 프론트엔드 정적 파일
│   ├── current/                   # 현재 버전 (심볼릭 링크)
│   │   ├── index.html
│   │   └── assets/
│   └── releases/                  # 릴리스 히스토리
│       ├── 20250103-120000/
│       └── 20250103-140000/      # 최신 버전
│
├── data/                          # 데이터 저장소
│   ├── files/                     # 업로드 파일 (MMS 이미지 등)

└── scripts/                       # 운영 스크립트
    ├── deploy-backend.sh

```

### 5.2 사용자 및 권한

```
┌─────────────────────────────────────────────────────┐
│  사용자 그룹 구성                                   │
├─────────────────────────────────────────────────────┤
│                                                     │
│  linkwave (사용자)                                  │
│  ├─ 그룹: linkwave, www-data                       │
│  ├─ 역할: 백엔드 JAR 실행                          │
│  └─ 권한: /opt/linkwave/backend (rwxr-xr-x)        │
│                                                     │
│  www-data (사용자)                                  │
│  ├─ 그룹: www-data, linkwave                       │
│  ├─ 역할: Nginx가 프론트엔드 서빙                  │
│  └─ 권한: /opt/linkwave/frontend (rwxr-xr-x)       │
│                                                     │
│  공유 디렉토리: /opt/linkwave/data/files            │
│  ├─ 권한: 775 (rwxrwxr-x)                          │
│  ├─ 소유: linkwave:linkwave                        │
│  ├─ 백엔드: 파일 쓰기 가능 (linkwave)              │
│  └─ Nginx: 파일 읽기 가능 (www-data는 그룹 멤버)   │
└─────────────────────────────────────────────────────┘
```

**핵심 포인트:**
- ✅ 백엔드와 Nginx가 파일을 공유할 수 있도록 그룹 권한 설정
- ✅ 보안을 위해 최소 권한 원칙 적용
- ✅ 설정 파일은 600 권한으로 보호

### 5.3 systemd 서비스 관리

```bash
# 백엔드 서비스 관리
sudo systemctl start linkwave-backend    # 시작
sudo systemctl stop linkwave-backend     # 중지
sudo systemctl restart linkwave-backend  # 재시작
sudo systemctl status linkwave-backend   # 상태 확인

# 로그 확인
sudo journalctl -u linkwave-backend -f
```

**서비스 설정 (/etc/systemd/system/linkwave-backend.service):**
```ini
[Service]
User=linkwave
Group=linkwave
ExecStart=/usr/bin/java -jar /opt/linkwave/backend/current/linkwave-backend.jar
Restart=always
```

```
└─────────────────────────────────────────────────────────┘
```


### 6.3 배포 방식 - 심볼릭 링크 (Symbolic Link) 전략

#### 6.3.1 심볼릭 링크란?

**심볼릭 링크**는 파일이나 디렉토리를 가리키는 특수한 포인터입니다. Windows의 "바로가기"와 유사하지만, Linux/Unix 시스템에서 실제 파일처럼 동작합니다.

```
┌──────────────────────────────────────────────────────────┐
│  심볼릭 링크 개념                                        │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  current (심볼릭 링크)  ───→  releases/20250103-140000/ │
│                                  (실제 디렉토리)         │
│                                                          │
│  • current는 실제 디렉토리가 아닌 "가리키는 포인터"     │
│  • 애플리케이션은 current를 실제 경로처럼 사용          │
│  • 링크를 변경하면 즉시 다른 디렉토리로 전환            │
└──────────────────────────────────────────────────────────┘
```

#### 6.3.2 배포 프로세스 상세

```
┌─────────────────────────────────────────────────────────────┐
│ STEP 1: 배포 전 상태                                        │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  /opt/linkwave/backend/                                     │
│  ├── current → releases/20250103-130000/                    │
│  │              (현재 서비스가 이 경로를 사용)              │
│  └── releases/                                              │
│      ├── 20250103-120000/  ← 2시간 전 버전                  │
│      └── 20250103-130000/  ← 현재 실행 중 (v1.2.3)          │
│                                                             │
│  systemd 서비스 설정:                                       │
│  ExecStart=/usr/bin/java -jar \                             │
│    /opt/linkwave/backend/current/linkwave-backend.jar       │
│                                                             │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ STEP 2: 새 버전 준비 (서비스는 계속 실행 중)                │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1️⃣ 새 릴리스 디렉토리 생성                                  │
│     $ RELEASE_DIR="releases/20250103-140000"                │
│     $ mkdir -p $RELEASE_DIR                                 │
│                                                             │
│  2️⃣ 빌드된 JAR 파일 복사                                     │
│     $ cp build/libs/*.jar $RELEASE_DIR/linkwave-backend.jar │
│                                                             │
│  /opt/linkwave/backend/                                     │
│  ├── current → releases/20250103-130000/  ← 아직 이전 버전  │
│  └── releases/                                              │
│      ├── 20250103-120000/                                   │
│      ├── 20250103-130000/  ← 실행 중 (v1.2.3)               │
│      └── 20250103-140000/  ← 새 버전 (v1.3.0) 준비 완료!    │
│                                                             │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ STEP 3: 심볼릭 링크 전환 (원자적 연산)                      │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  3️⃣ 심볼릭 링크 업데이트 (ln -sfn 명령어)                    │
│     $ ln -sfn releases/20250103-140000 current              │
│                                                             │
│     옵션 설명:                                              │
│     • -s: 심볼릭 링크 생성                                  │
│     • -f: 기존 링크 강제 덮어쓰기                           │
│     • -n: 원자적 연산 (중간 상태 없음)                      │
│                                                             │
│  /opt/linkwave/backend/                                     │
│  ├── current → releases/20250103-140000/  ← 즉시 전환!      │
│  └── releases/                                              │
│      ├── 20250103-120000/                                   │
│      ├── 20250103-130000/  ← 이전 버전 (보관)               │
│      └── 20250103-140000/  ← 새 버전을 가리킴                │
│                                                             │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ STEP 4: 서비스 재시작                                       │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  4️⃣ systemd 서비스 재시작                                    │
│     $ systemctl restart linkwave-backend                    │
│                                                             │
│     서비스가 재시작되면서:                                  │
│     /opt/linkwave/backend/current/linkwave-backend.jar      │
│     → 이제 releases/20250103-140000/linkwave-backend.jar   │
│       (새 버전 v1.3.0)을 실행                               │
│                                                             │
│  5️⃣ 헬스체크로 정상 동작 확인                                │
│     $ curl http://localhost:8080/actuator/health            │
│     {"status":"UP"}  ← OK!                                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ STEP 5: 이전 릴리스 정리 (선택)                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  6️⃣ 오래된 릴리스 삭제 (최근 5개만 유지)                     │
│     $ cd releases                                           │
│     $ ls -t | tail -n +6 | xargs rm -rf                     │
│                                                             │
│  최종 상태:                                                 │
│  /opt/linkwave/backend/                                     │
│  ├── current → releases/20250103-140000/                    │
│  └── releases/                                              │
│      ├── 20250103-120000/  ← 삭제됨                         │
│      ├── 20250103-130000/  ← 롤백용 보관                    │
│      └── 20250103-140000/  ← 현재 실행 중 (v1.3.0)          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

#### 6.3.3 롤백 프로세스 (문제 발생 시)

```
┌─────────────────────────────────────────────────────────────┐
│ 긴급 롤백 시나리오                                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ⚠️ 문제 발견: v1.3.0에서 심각한 버그 발견!                 │
│                                                             │
│  현재 상태:                                                 │
│  current → releases/20250103-140000/  (문제 있는 버전)      │
│                                                             │
│  롤백 명령 (2개만 실행하면 됨):                             │
│  ┌─────────────────────────────────────────────────────┐  │
│  │ $ ln -sfn releases/20250103-130000 current          │  │
│  │ $ systemctl restart linkwave-backend                │  │
│  └─────────────────────────────────────────────────────┘  │
│                                                             │
│  롤백 완료 시간: 약 10초!                                   │
│  ├─ 링크 변경: 1초                                         │
│  ├─ 서비스 재시작: 5-10초                                  │
│  └─ 헬스체크: 2초                                           │
│                                                             │
│  롤백 후:                                                   │
│  current → releases/20250103-130000/  (안정 버전)           │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

#### 6.3.4 심볼릭 링크 배포의 장점

**1. 즉시 롤백 (Instant Rollback)**
```
기존 방식:
  문제 발견 → 이전 JAR 찾기 → 다시 빌드 → 재배포 → 30-60분 소요

심볼릭 링크 방식:
  문제 발견 → ln -sfn 명령 1회 → systemctl restart → 10초 완료!
```

**2. 무중단 준비 (Zero-Downtime Preparation)**
```
• 새 버전 파일을 복사하는 동안: 서비스 정상 실행 ✅
• 심볼릭 링크 변경은 원자적 연산: 중간 상태 없음 ✅
• 서비스 재시작만 짧은 다운타임 발생: 5-10초
```

**3. 다중 버전 관리**
```
releases/
├── 20250103-110000/  ← v1.2.1 (3시간 전)
├── 20250103-120000/  ← v1.2.2 (2시간 전)
├── 20250103-130000/  ← v1.2.3 (1시간 전)
└── 20250103-140000/  ← v1.3.0 (현재)

언제든지 원하는 버전으로 즉시 전환 가능!
```

**4. 블루-그린 배포 가능**
```
blue/    ← 이전 버전 (안정)
green/   ← 새 버전 (테스트)

테스트 완료 후: current → green/
문제 발생 시: current → blue/
```

**5. A/B 테스트 용이**
```
# 사용자 10%에게만 새 버전 라우팅 (Nginx 설정)
# 문제 없으면 100%로 확대
# 문제 있으면 즉시 0%로 축소
```

#### 6.3.5 실제 GitLab CI/CD 배포 스크립트

```bash
# .gitlab-ci.yml의 deploy 스크립트
deploy:prod:
  script:
    # 타임스탬프로 릴리스 디렉토리 생성
    - RELEASE_DIR="/opt/linkwave/backend/releases/$(date +%Y%m%d-%H%M%S)"

    # 새 버전 준비
    - sudo -u linkwave mkdir -p $RELEASE_DIR
    - sudo -u linkwave cp build/libs/*.jar $RELEASE_DIR/linkwave-backend.jar

    # 심볼릭 링크 원자적 전환
    - sudo -u linkwave ln -sfn $RELEASE_DIR /opt/linkwave/backend/current

    # 서비스 재시작
    - sudo systemctl restart linkwave-backend

    # 헬스체크 (최대 30초 대기)
    - |
      for i in {1..30}; do
        if curl -f http://localhost:8080/actuator/health; then
          echo "✅ 배포 성공!"
          exit 0
        fi
        sleep 1
      done
      echo "❌ 배포 실패 - 롤백 필요!"
      exit 1

    # 이전 릴리스 정리 (최근 10개만 보관)
    - cd /opt/linkwave/backend/releases
    - sudo -u linkwave ls -t | tail -n +11 | xargs -r rm -rf
```

```
/opt/linkwave/frontend/

│                ├── index.html

배포 시:
```

**요약:**
- ⚡ **10초 롤백**: 심볼릭 링크 + 서비스 재시작만으로 즉시 복구
- 📦 **버전 보관**: 최근 5-10개 릴리스를 항상 유지하여 안전성 확보
- 🔄 **원자적 전환**: ln -sfn 명령은 중간 상태 없이 한 번에 전환
- 🛡️ **안전한 배포**: 새 버전 준비 → 테스트 → 전환 → 검증 → 이전 버전 정리

## 9. Q&A

### 9.1 자주 묻는 질문

**Q1: 왜 DB를 Web DB와 Message DB로 분리하나요?**

A: 성능 최적화와 장애 격리를 위해서입니다.
- Web DB는 사용자 인터페이스에 최적화 (빈번한 읽기/쓰기)
- Message DB는 대량 발송 처리에 최적화
- 서로 영향을 주지 않아 안정성 향상

**Q2: Java 21과 Spring Boot 4.0은 안정적인가요?**

A: 네, 안정적입니다.
- Spring Boot 4.0은 2025년 11월 GA 릴리스
- Java 21은 LTS 버전으로 장기 지원
- 철저한 호환성 테스트 완료

**Q3: 기존 시스템과 어떻게 통합되나요?**

A: API 기반 연동으로 유연하게 통합 가능합니다.
- REST API 제공
- 표준 메시지 포맷 (ums_msg)
- 기존 발송 에이전트와 독립적 동작

**Q4: 배포 시 다운타임이 있나요?**

A: 최소한의 다운타임만 발생합니다.
- 백엔드: systemd restart 시 5-10초
- 프론트엔드: Nginx reload로 무중단
- 심볼릭 링크 방식으로 즉시 롤백 가능

**Q5: 개발 인력은 어떻게 구성되나요?**

```yaml
stages:
  - build
  - test
  - deploy

build:
  image: eclipse-temurin:21-jdk
  script:
    - ./gradlew clean build -x test

deploy:prod:
  script:
    - export RELEASE_DIR="/opt/linkwave/backend/releases/$(date +%Y%m%d-%H%M%S)"
    - sudo -u linkwave mkdir -p $RELEASE_DIR
    - sudo -u linkwave cp build/libs/*.jar $RELEASE_DIR/
    - sudo -u linkwave ln -sfn $RELEASE_DIR /opt/linkwave/backend/current
    - sudo systemctl restart linkwave-backend
  when: manual
  only:
    - main
```
