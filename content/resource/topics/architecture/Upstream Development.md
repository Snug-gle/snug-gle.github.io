- 업스트림 개발의 주요 이점
	1. 문제 예방 -> 유지보수 비용 절감
		- ex. 공통 API 명세 & DTO 선정의.. 백엔드/프론트 간 충돌 감소
		``` java
		// DTO 정의
		public class UserRequest {
			@NotBlank
			private String email;

			@NotBlank
			private String name;
		}

		@PostMapping("/user")
		public ResponseEntity<?> createUser(
			@RequestBody @Valid UserRequest req
		) {
			// 유효성 자동 검사, Swagger 명세 생성됨
			return ResponseEntity.ok("생성완료");
		}
		```
	2. 재사용성과 확장성 증가
		-  공통 모듈, 유틸리티, 공통 플랫폼을 먼저 구축하면 반복 구현을 방지
		- ex. 인증, 로깅, 권한 관리 등 재사용 가능한 핵심 컴포넌트를 선개발
	3. 개발 일관성 유지
		- 초기 설계, 코드 컨벤션, 폴더 구조, 라이브러리 전략 등을 통일
	4. 테스트, 보안 등 품질을 초반부터 내재화
		- shift-left 전략에 따라 보안, 테스트, 문서화 등을 초기에 설계에 반영
		- -> 출시 후 이슈 대응이 좋고 QA  팀 의존도가 낮아짐
	5. 팀 전체 생산성 향상
		- 업스트림 단계에서 기주점이 명확하면 중간 단계 개발자가 불필요한 의사결정을 하지 않게 됨
		- ex. 디자인 시스템, API 스펙, 상태 관리 정책 등을 초기에 공유
	6. 비즈니스 의사결정 속도 증가
		- 기술 부채를 줄이고, 유연한 구조를 갖추면 새로운 요구사항 대응이 빨라짐
		- 기획자나 PO가 요구 변경할 때 빠르게 반영 가능
	7. 엔지니어의 만족도 향상
		- 구조적 개발, 기술적 성장 기회가 많고, '단순 반복 노동'에서 벗어날 수 있음
- 단점
	- 초기 설계 시간 증가
		- -> 요구사항이 명확하지 않아도 유연한 추상화로 대응
	- 조직 내 설득 필요
		- -> ROI 분석 및 생산성 지표 공유
	- 잘못된 추상화 -> 오히려 발목 잡음
		- -> 실제 유즈케이스 기반 MVP로 검증
